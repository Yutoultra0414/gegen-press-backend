# スクショ自動入力機能について

ニュース投稿・コラム投稿の画面に「スクリーンショットから自動入力」ボタンを追加しました。
SNS投稿などのスクショをアップロードすると、Gemini APIが内容を読み取り、日本語に翻訳・要約した上で、
見出し・概要・本文・ハッシュタグ・サブカテゴリ（ニュースの場合は記事の種類・記者名の候補も）を
自動でフォームに入力します。**そのまま投稿はされません。** 必ず内容を確認・修正してから投稿する運用です。

## 必要な設定（デプロイ前に）

1. Google AI Studio（https://aistudio.google.com/）でGemini APIキーを発行
2. Vercelのプロジェクト設定 → Environments → Production の環境変数に
   `GEMINI_API_KEY` としてそのキーを登録（Sensitiveのままでよい）
3. `firestore.rules` を今回の分に更新（Firebaseコンソールへの貼り直し必須）
4. Vercelを再デプロイ（GitHubにpushすれば自動）

## 仕組み（技術的な要点）

- `api/analyze-screenshot.js` が新しく追加されたVercelサーバーレス関数です。GitHubにpushすると
  Vercelが自動的にこれを `/api/analyze-screenshot` というURLのAPIとして動かします。
- **Gemini APIキーはこの関数の中（サーバー側の環境変数）にしか存在しません。** ブラウザの画面や
  ソースコードには一切出てきません。
- **1日10回/ユーザーの上限は、Firestoreのセキュリティルールで強制しています。**
  `aiUsage` という新しいコレクションに、ユーザーごと・日付ごとの利用回数を記録し、
  ルール側で「10回を超えたら書き込みを拒否する」という制御をしています。
  サーバーレス関数自身は「回数を数える」処理をしておらず、
  「Firestoreへの回数+1が成功したかどうか」だけを見て、成功した時だけGeminiを呼び出します。
- 画像を送ったユーザーが本人であることの確認も、最終的にはFirestore自身が行います
  （偽物のログイン情報を送っても、Firestoreへの書き込みリクエスト自体が拒否されます）。

## 正直に：検証できていないこと

- コード上のロジック（回数制限の分岐、フォームへの反映処理）は、実際のFirebase/Gemini通信を
  モックに置き換えてテストし、正しく動くことを確認済みです。
- ただし、**実際のGemini APIとの通信そのものは、この開発環境にネット接続が無いため一度も
  試せていません。** モデル名（`gemini-3.6-flash`）は2026年8月時点の検索で確認したものですが、
  実際に動かして初めて分かる調整（プロンプトの精度、レスポンス形式のズレなど）が発生する
  可能性があります。デプロイ後、実際にスクショを試してみて、精度や挙動がおかしければ教えてください。
- Firestoreの利用回数カウンターは「読み取り→書き込み」の2段階です。ごく稀に同時アクセスが
  重なると、上限が10回ぴったりではなく11〜12回になる可能性があります（大きな実害はない想定です）。
